# IA-first · living learning · optimize the working guide

The product is designed **around AI**, not the other way around.  
Harness (human name) = **working guide** (`ux-craft.md`).

## 1. IA-first product
- Every new screen or flow gets an **AI entry** in the same iteration (chat, help, interpret).  
- Do not ship a mute admin if the app already has an assistant.  
- Chat: Enter sends · Shift+Enter newline · **voice always** (`ux-craft` §6).

## 2. Learning → chat context (ahead of time)
If there is a working guide, academy, tour, tutorial, or learning section:

1. **Persist** that content in the product mechanism (skill, tour file, API) — not only in the Cursor chat.  
2. The **in-app AI chat** has it as prior context (inject or retrieve; Context7/RAG is not the UX fix).  
3. New requirement or feature → **update tour + learning pack in the same iteration**.  
4. New operator flow without a guide → minimal guide + index it for the chat.

## 3. Optimize the working guide on every development
At close (`self-improve.md` + `crystallize.md`):

1. Crystallize the critical and what worked.  
2. **Suggest** 1–3 improvements: command, shortcut, execution, or working-guide rule.  
3. Generic and safe → promote (`promote-harness.md`).  
4. Product-specific → skill + learning pack (the in-app chat inherits it).

Do not recompact the thread (`context-discipline.md`).

## When to load
Feature · UI · AI chat · tour/academy · iteration close · new app.
